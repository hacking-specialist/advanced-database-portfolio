# Twelve-week development plan

| Weeks | Component | Next practical evidence |
|---|---|---|
| 1–2 | Design | Review supplied ERD, assumptions, data dictionary and normalisation |
| 3 | Implementation | Run PostgreSQL scripts, save outputs, explain constraints and correct findings |
| 4–5 | Optimisation | Generate larger deterministic data; measure queries and plans before/after justified indexes |
| 6–7 | Transactions | Capture commit, rollback, two-session copy contention, isolation and lock behaviour |
| 8–9 | NoSQL | Implement MongoDB catalogue, CRUD and aggregation; evaluate embedding versus references |
| 10–11 | Distributed/cloud | Configure primary/standby; capture replication and availability/consistency observations |
| 12 | Final documentation | Reproduce experiments; write 2–3 page summary, personal reflection and references |

All five technical components now have implementations and recorded results from 13 November 2026. The schedule remains a guide for genuine continued maintenance, review and improvement over the required period, not a claim that the weeks have already elapsed. Keep commands, versions and outputs together, record actual dates, and make meaningful commits. Confirm private repository visibility and assessor access. Never include credentials or real borrower records.
